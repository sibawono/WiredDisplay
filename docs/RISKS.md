# Risk Register

Updated 2026-11-16. Severity follows the project policy (S0 worst). Likelihood: L/M/H.

| ID | Risk | Sev | Likelihood | Mitigation | Status |
|---|---|---|---|---|---|
| R-01 | A display change, a Wi-Fi change on the iPad, or unplugging the cable strands the headless Mac (its only screen is Sidecar on the same iPad; E-05b was deferred for this reason) | S0 | M | No automatic main-display change (D-007); probe self-reverts and removes the display on any change to existing displays; display removal is tied to process lifetime, so killing the process restores the set. Before E-03 the user should have a second way in (Screen Sharing or SSH from another device). | Open — E-03 not run |
| R-02 | Input injection without authentication | S0 | M once input exists | Mac dials out only (D-004); auth flag reserved and refused (D-006); injection limited to supervised PoC until pairing lands | Open — by design until Phase 5 work is pulled forward |
| R-03 | macOS update changes or removes `CGVirtualDisplay` | S1 | M per major release | Fail-closed shim with encoding checks (D-001); `wd-vdisplay-probe check` as a canary to run after every OS update | Mitigated in code, cannot be removed |
| R-04 | usbmuxd behaviour changes, or loopback delivery to third-party apps is restricted | S1 | L | Works today (E-05 HW, iPadOS on iPad14,10); re-run `wd-usbmux-probe echo` after each OS update; optional explicit Wi-Fi mode as a documented alternative | Mitigated: verified on the current OS |
| R-05 | Link bandwidth limits bitrate | S4 | L | **Corrected (BUG-032):** link is 10 Gb/s; measured up to 1,386 Mbit/s per direction through usbmuxd. 80 Mbit/s video default leaves ample headroom | Mitigated |
| R-06 | iPad app must stay in the foreground; background or lock stops the listener | S2 | **Observed** (E-05: switching to Sidecar ended a transfer) | Disable idle timer while connected; reconnect state machine; document | Accepted limitation |
| R-07 | Another iPad app binds the port first, or connects to loopback and holds the single slot | S2 (S0 once input rides this path) | L | Mutual authentication before any data is trusted (D-006); fail visibly if bind fails | Open until auth |
| R-08 | Free Personal Team: iPad app expires every 7 days; limited App IDs | S2 | H (observed) | Document rebuild/reinstall; a paid membership removes it | Accepted or user decision |
| R-09 | Virtual camera impossible without paid membership (restricted system-extension entitlement) | S2 | H | None on a free team | **Blocked** — user decision |
| R-10 | HAL audio plug-in refuses to load with development signing | S2 | M | Test early in Phase 6 with a minimal null device before building the feature | Open |
| R-11 | WindowServer does not keep the requested HiDPI mode or adds the new display to the existing mirror set | S2 | M (OpenDisplay needs a re-assert loop) | Observe in E-03 (`during` snapshot reports mode and mirror state); re-assert in Phase 2 | Open |
| R-12 | ScreenCaptureKit mis-identifies virtual displays in some configurations | S2 | L–M | Match by `CGDirectDisplayID`; verify captured dimensions against the created mode | Open |
| R-13 | Pre-login, FileVault and Recovery have no display | S1 for the user if unaware | H (platform) | Document; require a physical recovery path; never enable auto-login or weaken FileVault | Accepted limitation |
| R-14 | Three third-party display tools already run here (Sidecar, BetterDisplay, Sidecar Travel) and may fight over arrangement and mirroring | S2 | M | Record the before/after arrangement in every display experiment; do not touch displays we did not create | Open |
| R-15 | Screen Recording and Accessibility grants are per binary; unsigned or re-signed builds lose them | S3 | H | Stable bundle ID and signing identity for the host app from Phase 1 | Open |
| R-16 | Host killed (crash, `kill -9`) while a synthetic mouse button is held: WindowServer may keep it pressed | S2 | L | `releaseAll` on every disconnect, input toggle-off and quit; menu Quit waits 1 s for teardown. A hard kill cannot run cleanup — press and release the trackpad/mouse once to clear | Accepted |
| R-17 | Building ahead of the hardware gate (D-012): hardware-only defects arrive together in one session | S2 | H | Single runbook with per-step expected results; host logs to ~/Library/Logs/WiredDisplayHost.log; one-command recovery (quit host, Sidecar Travel reconnect) | Accepted by user |
| R-18 | Keyframe storm on a slow link: a large keyframe lets P-frames queue past the limit, triggering another keyframe | S3 | L–M | Video queue 6 frames; measured link ≥119 Mbit/s vs 30 Mbit/s default bitrate; watch "video dropped" in the host log | Open |
| R-19 | Desktop motion limited to ~35–45 fps at the source: macOS composites the displays only ~35–45 times/s while Sidecar (avconferenced ~41 % CPU) and a BetterDisplay mirror run, even when an app draws at 60 fps | S2 | H (measured) | Pipeline adds no loss (capture = encode = present, 0 dropped). Capture interval set to half the frame period (removes 50 ms gaps). Re-measure with WiredDisplay as the only remote display (Sidecar off) in Phase 2; move the project out of iCloud-synced Documents (cloudd ~97 % CPU) | Open |
